Spec: `docs/POST-LAUNCH.md` section "H. UI/UX review 2026-09-05". Rows are

## Global Constraints

- Next.js app router, Tailwind v4, tokens in `src/app/globals.css`
  (`--phosphor`, `--phosphor-dim`, `--hairline`, `--chassis`, …). Use tokens,
  never raw hex.
- Three themes (green / amber / paper) — every change must look right in all
  three; paper has `--glow: transparent`.
- Every interactive control ≥ 44×44 px hit area at 390 px width. Desktop
  F-keys may stay 33 px tall (pointer precision), but everything else in H1–H3
  meets 44 px at both widths.
- Motion: ≤ 300 ms except H11 (600 ms, explicitly allowed); transform/opacity
  (and border-color for hover) only; `prefers-reduced-motion: reduce` path
  keeps working and removes transforms. Hover gated behind
  `@media (hover: hover) and (pointer: fine)`.
- Verification per task: `npm test && npm run lint && npm run typecheck &&
  npm run build` all green (lint is `--max-warnings 0`). Visual checks with
  Playwright against `npm run dev -- --port 3106` at 1280 and 390 px; kill
  the server afterwards.
- Keep `docs/POST-LAUNCH.md` status column updated: mark each H row
  `IN PR` when the task lands (the controller fills in the PR number).
- Conventional-style commit subjects like the existing history.

## Task 2: H9–H14 — motion

| # | Item | Evidence | Fix | Done when |
|---|---|---|---|---|
| H9 | Cartridge spin-up costs 500 ms and is a text swap | `Cartridge.tsx` `setTimeout(router.push, 500)`; "▸ SPIN-UP…" replaces the one-liner, nothing moves | Navigate at 250 ms; `translateY(1px)` + phosphor border pulse during the wait; reduced-motion path unchanged | Click-to-route ≤ 250 ms, motion visible |

| H13 | No hover on cartridges / F-keys | Only `hover:underline` on text links | `transition: border-color 120ms ease` to a brighter phosphor border, gated by `@media (hover: hover) and (pointer: fine)` | Hover visible on desktop, inert on touch |
| H14 | F-key release snaps back | `active:translate-y-[2px]` with no transition | Keep instant press; `transition: transform 100ms ease-out` for release | Press instant, release eased |

Notes:
- H9 first: it is the only row that costs the visitor time. Reduced-motion
  path: still navigate at 250 ms, no translate/pulse.
- H10: keep the overlay mounted for the 150 ms fade after the 1200 ms timer,
  but a key/pointer skip unmounts immediately (no fade). Existing boot tests
  in `tests/` must stay green; extend them if they assert the unmount timing.
- H11: only paths that are new since the previous stage animate; paths
  already on screen do not redraw. Reduced motion: no draw animation.
- H14: "instant press" means `transition` applies on release only — use
  `transition: transform 100ms ease-out` at rest and `active:transition-none`.
